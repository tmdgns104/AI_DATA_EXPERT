# Notebook Output Style Contract V6

- 원본 문제 셀은 그대로 보존한다.
- 내부 Argument Ledger / Evidence ID / Verifier 세부 구현은 최종 Notebook에서 숨긴다.
- Markdown은 문제 이해, 전처리 이유, 모델 비교, 결과 해석, 결론처럼 꼭 필요한 구간에만 쓴다.
- 한 Markdown 블록은 짧게 유지한다.
- 코드만 봐도 알 수 있는 주석은 쓰지 않는다.
- 주석은 왜 그렇게 했는지 설명할 때만 쓴다.
- 결과 숫자 뒤에 짧은 해석을 붙인다.
- 성능 차이가 작으면 작다고 쓴다.
- 모르는 요구사항은 임의로 확정하지 않고 REVIEW/가정으로 표시한다.
- 자연스러운 한국어를 사용하며 `~했음`, `~확인해봄`, `~사용함` 같은 간결한 표현을 허용한다.
